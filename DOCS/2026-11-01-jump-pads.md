# Olimar and Pikmin fall short of jump pads (2026-11-01)

## Prior attempt

`740373e` ("Jump pads: log the launch, and use the motor's own gravity") changed
`OlimarDriver.BuildInput` to replay a pad with
`Physics.gravity * native.GravityScale` instead of `Physics.gravity`, and logged every
pad launch. It did not fix the shortfall.

## Why it did not work

The gravity value only applies when `padLaunch` is true:

```csharp
bool padLaunch = native.JumpPadLaunch;   // motor.disableAirControlUntilCollision
... launch_captain(..., padLaunch ? padGravity : 0f, B(padLaunch));
```

`JumpVolume.OnTriggerStay` sets `disableAirControlUntilCollision` (all pads in every
stage have `AllowAirControl = 0`; checked in the game's bundles), but `CharacterMotor`
clears it again in `OnMovementHit` — normally the floor — before the next `FixedUpdate`
reads it. So the host saw a real pad as ordinary knockback:

- `padLaunch` false, so the sim used its own gravity (550 sim/s² = 22 m/s²) instead of
  the pad's 9.81 m/s². A geyser's authored throw is `jumpVelocity.y ≈ 54 m/s`; with
  22 m/s² its apex is less than half the pad's and it lands well short.
- `squad` false, so the Pikmin never got the takeoff cue and did not repeat the arc.

The gravity change itself was also a no-op: the player's `CharacterMotor` has
`gravityScale = 1` and `gravityMultiplier = 1`, so `GravityScale` is 1 and the value was
the same as before.

## Fix

1. `PikminWorld.JumpPads.cs` hooks `JumpVolume.OnTriggerStay`. After the original runs,
   it finds the `CharacterBody` in the trigger and, if it has an `OlimarDriver`, records
   the pad's own `jumpVelocity` (aligned to `transform.up` when
   `alignJumpVelocityToTransform`). That is the exact throw, independent of the motor's
   flag and of a frame of gravity already applied to `motor.velocity`.
2. `OlimarDriver.BuildInput` prefers that recorded throw for `0.25 s`, **before** the
   smoother's `MovedElsewhere` pose branch (a `Pose` there would zero the velocity the pad
   just gave him), calls `launch_captain` with the pad gravity and `squad = 1`, and ignores
   the pad's repeated `OnTriggerStay` reports until the captain lands (`padFlight`).
3. `NativeBody.JumpPadLaunch` keeps the flag for `0.2 s` after seeing it, as a fallback
   for any host or ordering where the hook does not fire.

The hook logs a warning if `OnTriggerStay` cannot be hooked, so a failure is visible
instead of silent.

## Verified facts

- Pads (base + DLC stages, geysers, bounce shrooms, elevators): `AllowAirControl = 0`,
  `jumpVelocity.y` ≈ 12–223 m/s, `time` 0.5–10 s.
- `CharacterMotor` gravity: `Physics.gravity * gravityScale * gravityMultiplier`
  (`gravityScale = 1`, `gravityMultiplier = 1`; hangtime gravity only with
  `KnockUpHitEnemies`).
- Sim gravity at rest: `ai.gravity = 550` sim/s²; the pad's is `245` (9.81 / 0.04).
